## 2026-10-20 夜间：密码彻底移出仓库

最终方案（`application.yml` 里已无任何真实密码）：

| 位置 | 用途 | 是否入库 |
|---|---|---|
| `olearning-server/config/application-local.yml` | 本地密码（默认 profile=local 加载） | 否，已 gitignore |
| 环境变量 `DB_PASSWORD` | 容器 / 服务器 | — |

- `application.yml`：`spring.profiles.default: local` + `password: ${DB_PASSWORD:}`。
- **关键坑**：本地配置文件必须放 `olearning-server/config/`（Spring Boot 的 `./config/` 自动搜索路径），
  **不能**放 `src/main/resources` —— 放 resources 会被打进 jar，容器里会覆盖 `DB_PASSWORD`，
  导致 docker-compose 用错密码连不上。已验证 jar 内 `application-local.yml` 条目数为 0。
- 启动工作目录必须是 `olearning-server`，否则找不到 `./config/`，此时退回 `DB_PASSWORD`。
- 三种场景都实测过：①有 config 文件 → 日志 `falling back to 1 default profile: "local"`，查库 200；
  ②移走 config + 设 `DB_PASSWORD`（正确密码）→ 查库 200；③移走 config 不设环境变量 → 连接失败（符合预期）。
- `application-example.yml` 改成指向 config 方案的完整模板（注意：中途误覆盖成只剩 datasource 段，已补回 server/app/jwt/upload）。
